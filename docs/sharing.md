# Journey sharing

Sign into Bramsee, open Profile and choose Start journey sharing. Allow GPS access and copy the resulting link only to someone you trust. Anyone with that unguessable link can view the latest location without signing in on the direct Cloudflare deployment. This is a bearer link: it is not restricted to a named contact. Do not publish or forward it broadly.

The sender uploads at most once every five seconds when a fresh GPS callback arrives. Uploads are serialized, time out after ten seconds, and check HTTP status and the server response. Profile shows the last successful upload age or an explicit failure. GPS permission, browser background restrictions, connectivity and expired sign-in sessions can interrupt updates. There is no artificial heartbeat that refreshes an old position's timestamp.

The recipient fetches the journey every ten seconds while the page is visible and refreshes when returning to the page. Location and map camera update automatically. Dragging the map pauses camera following; Follow shared location restores it. A position older than ninety seconds is marked paused/last known, rather than live. The recipient does not need to enable their own GPS. A failed fetch removes the displayed sharing marker and shows an unavailable message while polling retries. Stopped journeys return no coordinates or destination and remove the marker on the recipient's next successful poll (normally within ten seconds while visible).

Only the signed-in owner can update or stop a journey. Wrong-account writes return 404; ended sessions reject position writes with 409. A concurrent position update cannot reactivate a stopped journey. Stop is idempotent so a retried stop remains successful. Sharing stays active after reaching the destination until the owner chooses to stop, as requested. It has no automatic expiry; older journey records are not yet automatically purged. Phone locking or closing Bramsee can pause GPS. This is not an emergency monitoring service.

`npm run test:sharing` verifies display freshness and invalid/stopped position handling. `BRAMSEE_TEST_URL=http://127.0.0.1:4174 npm run test:sharing:integration` requires the isolated local Worker and `.sites-runtime/account-test-state` database. It verifies anonymous recipient reads, validation, same-origin/authentication, ownership, actual error responses, stopped-link privacy and concurrent stop/update. Test coordinates and accounts are disposable. Browser QA additionally moves the isolated test location and verifies automatic map updates and marker removal on stop. No production journey or real GPS is used for these tests.
